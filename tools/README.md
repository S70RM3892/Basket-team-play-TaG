# tools/ — art & audio pipeline (Basket Team-play TaG)

Everything in `game/Content/Art` and `game/Content/Audio` is generated by the scripts in this folder:
meshes are modelled with Python in Blender, sounds are synthesised with Python, and both are imported into a small
content-only Unreal project (`tools/assetproj`) and then copied into the game. Nothing is hand-edited, so the
whole set can be rebuilt in a few minutes.

The look is stylized fantasy, far from photo-real: chunky cel-shaded heroes with big heads and bean eyes, ink
outlines, a dusk sky with toon clouds, floating islands and a big pale moon, and a rooftop court dressed with a
vermilion shrine gate, paper-lantern strings and banners.

The game project (`game/BasketTaG.uproject`) is never opened, built or run by this pipeline.

| Folder | Contents |
|---|---|
| `blender/` | `sdf.py` (signed-distance modelling + surface nets), `sdfbake.py` (SDF → decimated mesh, outline hull, width fit), `heroes.py` (rig, feature library, build), `hero_designs.py` (one recipe per hero), `tagmesh.py` (mesh toolkit, `Part`, slot order), `palette.py` (colours per mesh and slot), `ball.py`, `court.py`, `city.py`, `sky.py`, `build_assets.py` (builds everything and exports FBX), `render_previews.py`, `scene_util.py` |
| `audio/` | `synth_sfx.py` (32 sound effects incl. three footfalls and two sneaker squeaks, 16-bit mono 44.1 kHz), `synth_music.py` (two music loops) |
| `import/` | `import_all.py` (runs in Unreal: MPC + materials, FBX import, material instances, sockets, portraits, sounds), `verify.py` (runs in Unreal: checks and the manifest), `copy_to_game.py` |
| `assetproj/` | `TaGAssets.uproject`, a content-only helper project (PythonScriptPlugin + EditorScriptingUtilities, no C++) |
| `art/` | `roster.json` (the 30 heroes), `manifest.json`, `verify_report.txt`, `previews/`, `CREDITS.md` |
| `build/` | generated intermediates (`fbx/`, `wav/`, `portraits/`, logs). Ignored by git through the root `build/` rule |
| `build_all.py` | runs every step in order |

## Rebuild everything

Close any Unreal Editor that has the game project open, because the copy step overwrites its packages. Then run:

```bash
"C:/Users/monns/AppData/Local/Programs/Python/Python312/python.exe" C:/TaG/tools/build_all.py
# options: --skip-previews  --skip-copy  --no-audio (art only: no SFX synthesis/import, copies game/Content/Art only)
```

### Step by step (the same commands that `build_all.py` runs)

```bash
PY="C:/Users/monns/AppData/Local/Programs/Python/Python312/python.exe"
BL="C:/Program Files/Blender Foundation/Blender 5.2/blender.exe"
UE="C:/Epic Games/UE_5.8/Engine/Binaries/Win64/UnrealEditor-Cmd.exe"
PROJ="C:/TaG/tools/assetproj/TaGAssets.uproject"

# 1. sound effects -> tools/build/wav/*.wav (+ sfx.json with durations and peaks)
"$PY" C:/TaG/tools/audio/synth_sfx.py

# 2. model everything and export one FBX per static mesh -> tools/build/fbx/**.fbx (+ assets.json)
"$BL" -b --factory-startup -P C:/TaG/tools/blender/build_assets.py

# 3. hero portraits -> tools/build/portraits/T_Portrait_<Key>.png (256x256, transparent; imported by step 4)
"$BL" -b --factory-startup -P C:/TaG/tools/blender/render_previews.py -- portraits

# 4. import into the helper project: MPC_TaG + materials, meshes, material instances, sockets, portraits, sounds
#    (add -nosounds inside the quotes to leave the sounds alone)
"$UE" "$PROJ" -run=pythonscript -script="C:/TaG/tools/import/import_all.py" -unattended -nop4 -nosplash -nullrhi

# 5. verify inside Unreal -> tools/art/verify_report.txt and tools/art/manifest.json
"$UE" "$PROJ" -run=pythonscript -script="C:/TaG/tools/import/verify.py" -unattended -nop4 -nosplash -nullrhi

# 6. copy tools/assetproj/Content/{Art,Audio} -> game/Content/{Art,Audio} (same paths; checked with SHA-256)
"$PY" C:/TaG/tools/import/copy_to_game.py            # or: --only Art

# 7. preview renders -> tools/art/previews/ (any of heroes,portraits,turnarounds,ball,court; default all)
"$BL" -b --factory-startup -P C:/TaG/tools/blender/render_previews.py -- heroes,turnarounds,ball,court
```

`build_assets.py` reads the court and hoop numbers from `game/Source/BasketTaG/Core/TaGTypes.h` every time it runs,
and `verify.py` compares the imported hoop against the same header. If the header changes, rebuild.

## How the heroes are modelled

Each hero is a recipe in `blender/hero_designs.py`: a skeleton (`skel(...)`: leg length, neck drop, shoulder and hip
spread, upper-body length; all in cm and scaled with the eye height) and a function that sculpts the 13 parts out of
signed-distance primitives in absolute rest-pose coordinates (spheres, ellipsoids, round cones, round boxes, tori,
cylinders, cones, half-spaces, noise displacement) combined with smooth union / subtraction / intersection.

- Every **group** is one closed shell with one material slot. Colour regions are separate shells that interpenetrate,
  so colour borders stay crisp.
- `sdf.surface_nets` polygonises each group on a voxel grid (`sdfbake.auto_voxel`: thinnest extent / 9, clamped to
  0.22–1.1 cm), projects the vertices back onto the surface, and `sdfbake.decimate` (Blender's collapse decimator)
  brings each group to its share of the part budget (`heroes.BODY_BUDGET`, weighted by area).
- Faces use a shared library in `heroes.py`: `human_head`, `bean_eyes` (glossy beans with a highlight, placed on the
  real surface by ray-marching the head's SDF), `smile`, hair caps / tufts / spikes / ponytails, mittens, shoes,
  armour plates, capes, kasa hats and so on.
- After baking, the whole hero is scaled in Y so that its overall width (outline included) matches the roster
  width; the eye height is exact by construction.
- `sdfbake.add_outline` adds an **inverted hull** to every part (vertices pushed out along the normals by 0.42 / 0.5
  / 0.6 / 0.75 cm for S / M / L / XL, faces reversed, decimated to 75 %) in slot `Outline`.
- Budget: **9000 triangles per hero including the outlines** (the body is capped at 9000 / 1.84 before the hull is
  added). `verify.py` checks it on the imported meshes.

## Conventions that C++ can rely on

**Axes and units.** Everything is in centimetres with UE axes: +X forward, +Y to the character's right
(left = −Y), +Z up. The Blender side models with +Y = left and exports with `bake_space_transform`, so Blender
(x, y, z) becomes UE (x, −y, z). `verify.py` checks this on the imported data, for example that the left sockets
have negative Y. Court, city and sky meshes are authored directly in UE coordinates.

**Heroes.** Each hero is **13 rigid static meshes**, `/Game/Art/Heroes/<HeroId>/SM_<HeroId>_<Part>` with the parts
`Pelvis Torso Head UpperArm_L UpperArm_R LowerArm_L LowerArm_R Thigh_L Thigh_R Shin_L Shin_R Foot_L Foot_R`.
They are animated by rotating the parts around their pivots.
- Rest pose: standing straight, arms hanging straight down, legs straight down, feet flat with the soles on z = 0.
- Every pivot is the joint with the parent. The sockets have zero rotation and unit scale. They are created by the
  FBX importer from `SOCKET_<name>` empties, and `import_all.py` re-checks them.
- The chain is Pelvis(`spine`) → Torso, Torso(`neck`) → Head, Torso(`shoulder_l/_r`) → UpperArm_L/R,
  UpperArm(`elbow`) → LowerArm, Pelvis(`hip_l/_r`) → Thigh_L/R, Thigh(`knee`) → Shin, Shin(`ankle`) → Foot.
- The Shin ends at the ankle; its socket `ankle` is the Foot pivot. The TaG ankle band is on the Shin, just above
  the ankle.
- `Foot_L/R`: pivot at the ankle; socket `sole` = centre of the sole on the floor, socket `toe` = front tip of the
  foot on the floor (in rest pose both have z = −ankle height relative to the pivot, and `toe` is in front of `sole`).
  Use them for planted-foot IK: put `sole` on the ground and roll the foot about `toe` at push-off.
- Leaf sockets: Head `eyes` (the first-person camera, between the eyes on the face surface), LowerArm `hand` (centre
  of the palm surface), Foot `sole` and `toe`.
- In rest pose the palms face the body midline: the left palm normal is +Y and the right palm normal is −Y. When the
  arms are raised forward, the palms face each other around the ball.
- Every part has the slot `Outline` (inverted hull). Keep it on the same mesh component.
- `manifest.json → heroes.<Id>` gives `pelvis_height` (the pivot height above the floor in rest pose),
  `eye_height`, `width`, the rest pivots of all parts, socket positions, triangle counts, slots and `portrait`.
- Portraits: `/Game/Art/UI/T_Portrait_<HeroId>` (256 × 256, transparent background, UI texture group, no mips).

**Material slots and instances.** Slot names come from the fixed list (`Body Accent Extra Skin Hair Dark Metal
White Team TaG Glow Jelly Window Net Board Court Paint Apron Water Sky Outline`). Every slot has its own
`MI_<Owner>_<Slot>`, stored next to the mesh. The owner is the hero id, `Ball`, `Hoop`, `Rooftop`, `RooftopProps`,
`RooftopProps_Furnace`, `CityA`, `CityB`, `Sea`, `SkyDome` or `Clouds`. These instances are meant to be overridden at
runtime:

| Slot | Default | Meant to be driven |
|---|---|---|
| `Team` | light grey `Color` | `Color` = team colour |
| `TaG` | dark body, white `Emissive`, `EmissiveStrength` 3 | `Emissive` (team colour) / `EmissiveStrength` |
| `Glow` | per mesh (hero accent at 4, lamps, lanterns, neon, ball core lines at 1.0) | `Emissive` / `EmissiveStrength` |
| `Window` | dark glass, warm or cool `Emissive`, `EmissiveStrength` **0** (off) | `EmissiveStrength` (try 3–20) as a district scores |
| `Outline` | ink `#1B1626` | `Color` = dark team tint (keep it dark, about 15–25 % of the team colour) |

**Materials** live in `/Game/Art/Materials`. All of them are **unlit** toon materials: the light comes from the
material parameter collection `MPC_TaG`, so they look the same on PC and Android and do not need scene lights.
Dynamic shadows are not received (use blob shadows if needed). Use manual exposure so that an unlit 1.0 shows as 1.0.

| Material | Blend | Parameters (defaults) |
|---|---|---|
| `M_TaGBase` | opaque | `Color`, `Emissive`, `EmissiveStrength` 0, `Roughness` 0.6, `Metallic` 0 |
| `M_TaGTranslucent` | translucent | the same plus `Opacity` 0.5 (Jelly slot) |
| `M_TaGWater` | opaque | `Color`, `Roughness` 0.06; stylised ripple bands from world position and time, horizon tint |
| `M_TaGOutline` | opaque | `Color` (inverted hull ink) |
| `M_TaGSky` | opaque, two-sided | none; gradient SkyGround / SkyHorizon / SkyZenith by view direction, sun glow along SunDir |
| `M_TaGParticle` | additive | `Falloff` 1.6, `Intensity` 2.0; colour from PerInstanceCustomData 0..2, alpha from 3 |
| `M_TaGParticleAlpha` | translucent | `Falloff` 0.8, `Intensity` 1.0; same custom data |

`M_TaGBase` result (emissive output): `Color × (lerp(ShadeColor, SunColor, band) + Ambient) + rim + Emissive ×
EmissiveStrength × VertexColor.R`, with `band = saturate((N·normalize(SunDir) − BandOffset) × BandSharpness + 0.5)`
and `rim = (1 − saturate(N·V))^RimPower × RimStrength × (0.45 + 0.55 band) × RimColor × Color`. `Roughness` and
`Metallic` are kept as parameters for compatibility but do not change the toon result. Only the window quads carry
vertex colours (R between 0.15 and 1.0); every other mesh reads 1.0.

The particle materials are for instanced static meshes (spheres, quads, rings…): set `NumCustomDataFloats = 4`
and write RGB into 0..2 and alpha into 3 per instance (the default is 1.0 when no custom data is set).

`MPC_TaG` defaults (UE world space, linear colours):

| Vector | Default | | Scalar | Default |
|---|---|---|---|---|
| `SunDir` (points to the light) | (0.52, 0.42, 0.74) | | `BandSharpness` | 7.0 |
| `SunColor` | (1.0, 0.93, 0.84) | | `BandOffset` | −0.05 |
| `ShadeColor` | (0.44, 0.41, 0.64) | | `RimStrength` | 0.42 |
| `RimColor` | (1.0, 0.72, 0.52) | | `RimPower` | 3.0 |
| `Ambient` | (0.05, 0.045, 0.07) | | | |
| `SkyZenith` | (0.10, 0.12, 0.34) | | | |
| `SkyHorizon` | (1.0, 0.56, 0.42) | | | |
| `SkyGround` | (0.16, 0.12, 0.2) | | | |

**Court and city.** All of these are authored in court coordinates: the origin is the middle of the baseline on the
floor, and the court spans x 0..1100, y −750..750. Spawn them at the identity transform.
- `SM_Hoop`: the board front face is at x = 120 (3 cm thick behind it), y ±90, z 290..395. The rim is a torus
  centred at (157.5, 0, 305) with a tube centre-line radius of 22.5 and a tube radius of 1.0, which is the torus that
  `TaGBallSim` collides with. Its inner edge is therefore at r = 21.5. The net is about 40 cm. The padded pole is at
  x = −100. Sockets `rim` and `net_bottom` are for effects.
- `SM_Rooftop`: the top surface is exactly z = 0. Slot `Court` covers x 0..1100, y ±750. Slot `Paint` covers
  x 0..580, y ±245. Slot `Apron` extends to x −600..1700, y ±1300. The slab is 100 cm thick and has one simple
  collision box.
- `SM_RooftopProps`: parapet and railing, four light towers (slot `Glow` lamps), stair hut, water tank, pipes, a
  gantry at the far end, the host building down to the sea, and the fantasy dressing: a vermilion shrine gate
  (x = −260, posts at y ±440, 7.4 m high) framing the hoop, paper-lantern strings (slot `White`, emissive) sagging
  between the light towers, and nobori banners along both sidelines (y −1000 and +940).
- `SM_RooftopProps_Furnace`: furnace stacks with glowing mouths and the blast furnace, all off the slab.
- Both props meshes keep out of x −150..1250, y −900..900 above the floor, and `verify.py` checks this.
- `SM_CityA_01..12`: ally district on the −Y side. `SM_CityB_01..12`: rival district on the +Y side. Each is a
  cluster 58–228 m from the court centre. The lower district rises from the sea at z = −4000. The towers reach up to
  z ≈ +16000.
- `SM_Sea`: a 2.4 km water plane at z = −4000, with lantern boats, stilt piers and 90 sky lanterns floating up from
  the bay (slot `Glow`).
- Collision: `SM_Rooftop` has a box, and `SM_Hoop` has boxes for the pole and the padding. No other mesh has simple
  collision.

**Sky.** Both meshes are in `/Game/Art/City`, authored in court coordinates; spawn at identity with collision off and
cast shadows off.
- `SM_SkyDome`: an inverted sphere of **radius 160000 cm (1.6 km) centred at (550, 0, 0)**, slot `Sky` →
  `M_TaGSky`. Everything else in the scene is inside it (the sea plane's far corners are clipped by it).
- `SM_Clouds`: eleven cel-shaded cumulus clouds on a ring 0.8–1.4 km out and 60–260 m up, three floating islands
  (rock, grass, a shrine gate and lanterns) 520–700 m out, and a large pale moon (slot `White`) in the −X / +Y sky.

**Sounds.** `/Game/Audio/SFX/<Name>` are SoundWave assets, mono 44.1 kHz, peak −3 dBFS. `AmbientLoop` is 24 s,
seamless and set to looping. The durations are in `manifest.json → sfx`.

## Changing things

- Roster (names, eye heights, widths, palettes, looks): `art/roster.json`.
- Colours: `blender/palette.py` (hero palettes come from the roster; `HERO_SLOTS` holds per-hero overrides such as
  hair, skin, glow). Rebuild, and the material instances are updated.
- Hero shapes: the recipe of the hero in `blender/hero_designs.py`; shared features in `blender/heroes.py`.
  `python render_previews.py -- turnarounds` (via Blender) renders `art/previews/heroes/<Key>.png` to check them.
- Toon lighting: `MPC_VECTORS` / `MPC_SCALARS` in `import/import_all.py` (defaults), or set `MPC_TaG` at runtime.
- City layout: the `CLUSTERS` list in `blender/city.py` (azimuth, distance, kind) and the random seeds.
- Sky: `blender/sky.py` (`SKY_RADIUS`, cloud ring, islands, moon).
- Previews only: court lines, lights and hero placement in `render_previews.py` are not part of the assets.

## Generated output that is not meant for git

`tools/build/`, `tools/assetproj/{Saved,Intermediate,DerivedDataCache}` are already covered by the root
`.gitignore`. `tools/assetproj/Content/` is the import workspace and duplicates `game/Content/Art` and
`game/Content/Audio`. Consider ignoring it.
