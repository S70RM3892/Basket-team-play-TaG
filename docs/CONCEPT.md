# Basket Team-play TaG — ゲーム構想 v0.4

> ロール制ヒーローFPS × バスケットボール。**PC・一人称視点**。
> キャラ・名前・ビジュアルはすべてオリジナル（既存タイトルの流用はしない）。

**v0.3での変更点**：エンジンをUE5.8に決めた。世界観（[WORLD.md](WORLD.md)）と技術設計（[TECH.md](TECH.md)）を追加した。「ゴールデンボール」は「オーバーコア」に改名した。

**v0.2での変更点**：スマホ向けの斜め上カメラをやめ、PC向けの一人称視点に切り替えた。

> **v0.4での大幅な上書き**：現実のバスケのルールを超えた競技「TaG」として作り直した。臨界コア、ケージ・アリーナ、三層リング、コア・ストライク、降下式コート、タッグ交代を追加した。§1の得点とショットクロック、§4のオーバーコアは [BEYOND.md](BEYOND.md) が優先する。

## 0. 三本柱（判断に迷ったらここに戻る）

| # | 柱 | 一言で |
|---|---|---|
| 1 | **協力が一番気持ちいい** | 1人で決める1点より、連携で決める1点のほうが得をする |
| 2 | **最後までチャンスがある** | 負けている側にも、腕前とチームワークで掴める逆転の機会が必ずある。ただし施しはしない |
| 3 | **一人称視点だからこその手応え** | シュート・パス・ブロック・スティールのすべてが「狙う」行為になる。エイム力がそのままバスケの上手さになる |

## 1. 試合モード

| 項目 | 3on3「ストリート」 | 5on5「アリーナ」 |
|---|---|---|
| コート | ハーフコート・ゴール1つ | フルコート・ゴール2つ |
| ロール構成 | ウォール1 / スコアラー1 / プレイメーカー1 | ウォール1 / スコアラー2 / プレイメーカー2 |
| 得点 | インサイド1・アウトサイド2・ディープ3 | インサイド2・アウトサイド3・ディープ4 |
| 勝利条件 | 21点先取、または10分経過時点でリードしている側 | 前半6分・後半6分の合計点 |
| ショットクロック | 12秒 | 20秒 |
| 想定試合時間 | 8〜11分 | 13〜16分 |
| 攻守交代 | ディフェンス側がボールを取ったら、アークの外に出してから攻撃を始める | 通常どおり切り替える |

- 3on3はFIBA 3x3の公式ルール（10分・21点・12秒）に合わせた。
- ディープラインは3Pラインのさらに外に引く。

## 2. キルの扱い：キルはなし。ダウンさせても仲間が触れれば即復帰

- 各キャラは **ガードゲージ** を持つ。体の接触や相手のスキルで削られる。
- ガードゲージが0になると **2.5秒ダウン** する。ボールを持っていればルーズボールになる。
- 味方が **F長押しで0.5秒** 触れると即座に起き上がり、起こした側と起こされた側の両方が1.5秒加速する。
- 一人称視点では、ダウン中の画面を **少し引いた三人称視点** に切り替え、周りの状況を見せる（ダウン中の時間も情報収集にあてられる）。

## 3. ロールとヒーロー（初期6体）

> アビリティ設計の原則（ズレ／ギャザー制／コア場）は [ABILITY_DESIGN.md](ABILITY_DESIGN.md) に、体格と当たり判定は [ROSTER.md](ROSTER.md) にまとめた。

| 名前 | ロール | スキル1（Shift） | スキル2（E） | ウルト（Q） | 連携ポイント |
|---|---|---|---|---|---|
| **ガンテツ** | ウォール | 照準の先に壁を4秒出す（パスもシュートも遮断） | ショルダーチャージ。当てた相手のガードを大きく削る | 「鉄壁圏」：ゴール下の円の中で、味方のブロックの当たり判定が大きくなる | 壁の横を通った味方が加速する |
| **ミナモ** | ウォール | 照準で狙った相手1人を引き寄せ、**マークを強制的に入れ替える**（体格のミスマッチを作る） | 自分の周りに減速フィールドを張る | 「渦」：範囲内の相手を中心へ集める | 引き寄せでマークを外し、フリーの味方を作る |
| **レイ** | スコアラー | 向いている方向へ短距離ブリンクしてドライブ | フェイダウェイ。次のシュートをブロックされにくくする | 「ゾーン」：5秒間、シュートの成功判定が広がる | パスを受けた直後はブリンクのクールダウンが短くなる |
| **ハヤテ** | スコアラー | スコープを覗いて照準を細かく合わせ、次のシュートの射程を延ばす | スポットアップ：止まっている間は、パスを受けてからのシュートの溜めが半分になる | 「ロックオン」：ブロックされないシュート。溜めが長く、ダウンさせられると中断する | アシストを受けたディープシュートの成功判定が広がる |
| **ツムギ** | プレイメーカー | 壁を貫通する糸パス（照準に乗せた味方へ） | 味方と糸でつながり、2人とも加速 | 「縫い寄せ」：照準で選んだ味方を自分の隣にワープさせる | 糸でつながった味方がシュートするとチェインが+1 |
| **ヒビキ** | プレイメーカー | 音波を撃ち、着弾した範囲の相手のガードを削る | 照準で狙ったダウン中の味方を遠距離から起こす | 「共鳴」：範囲内の味方のスキルのクールダウンを即リセット | ウルトの後にスキルをつなぐとシンクロ技が出やすい |

### 連携システム
1. **チェイン**：パスを2秒以内につなぐたびに+1（最大3）。シュートの成功判定が広がり、ウルトがたくさん溜まる。
2. **アシスト優遇**：ウルトの溜まり方は「アシスト1.5 ＞ 得点1.0」。
3. **シンクロ技**：2人が2秒以内に特定のスキルを重ねると、合体効果が出る（例：ツムギのワープ → レイのブリンク ＝ 遠距離からのアリウープ）。
4. **ピン（ホイールクリック）**：「パスくれ」「スクリーン行く」「ウルトあり」「起こして」。ボイスチャットを使わない人でも連携できる。

## 4. 逆転の仕組み

### 原則
- 逆転は **チャンスと腕前** で起きるようにし、負けている側への施しにはしない。
- 逆転しやすさを強くしすぎると序盤のリードが無意味になり、弱すぎると逆転が起きない。このバランスを数値で管理する。

### 仕組み
| 仕組み | 内容 |
|---|---|
| **クラッチタイム** | 残り1分（5on5は後半の残り1分）になると、ディープラインが少し前に出る |
| **オーバーコア** | クラッチタイムの開始時に、都市の余剰電力が中立のボールとしてコート中央に出る。奪って決めると＋3点（3on3）／＋5点（5on5）。勝っている側も取れる |
| **ストップの報酬** | ブロックとスティールで溜まるウルトの量を多めにする |
| **スコアは常に表示** | 「あと何本でひっくり返せるか」を見えるようにする |

### ガードレール
- クラッチタイムで動かせる点差は、最大で3on3が約8点、5on5が約12点。
- 指標：クラッチタイム開始時点で負けていた側の勝率が **20〜30%** に収まるようにする。

## 5. 一人称バスケの設計（v0.2の核心）

### 5.1 一人称ならではの問題と解決策

| 問題 | 解決策 |
|---|---|
| 自分のボールの状態が分かりにくい | 画面の下に手とボールを常に表示する。ドリブルのリズムを音と手の揺れで伝える |
| 後ろや横の状況が見えない | 味方は **壁越しでも輪郭線** で表示する。ボールは画面外にあっても、画面の端に矢印を出す。相手の位置は表示せず、足音で察知させる（首を振って状況を確認すること自体が上手さになる） |
| パスの宛先を選ぶのが難しい | **照準を向けた先にパスが飛ぶ**。照準から約15°以内に味方がいれば、その味方へ吸着する。右クリック長押しでロブパス |
| シュートがランダムに感じる | 照準でリングを狙い、左クリックを溜めて離す。照準のずれが左右の誤差に、離すタイミングが距離の誤差になる。ボールは実際の物理で飛び、リングで跳ね返る。相手に寄られているときだけ、わずかにばらつきを足す |
| 守備が受け身でつまらない | **ブロックは飛んでいるボールを照準で叩く**。**スティールはドリブル中のボールを狙ってクリックする**。どちらもFPSのエイム力で決まる |
| ダンクで画面が酔う | ダンクとレイアップは、ゴールの近くでジャンプしたときの状況に応じたアクションにする。カメラの揺れは最小限にし、三人称演出に切り替える設定も用意する |
| 3D酔い | FOVスライダー（80〜110°。広くすると画面の端が歪むことを説明付きで）。カメラの揺れ・歩行時の上下の揺れ・モーションブラーは個別にオフにできるようにする（Xboxのアクセシビリティガイドライン117に準拠） |

### 5.3 技術スタック（**UE5.8に決定**。詳細は [TECH.md](TECH.md)）

**採用：Unreal Engine 5.8**
- 一人称のテンプレートがあり、操作の手触りを早く試せる。
- キャラ移動の部品（Character Movement Component）に、サーバー権威での移動とクライアント側の予測・補正が最初から入っている。FPSのネットコードで一番重い部分を自前で書かずに済む。
- ボールはエンジンの汎用物理を使わず、**自前の放物線とリングとの簡易衝突** でサーバー側に計算させる。シュートした本人の画面だけは先に予測で動かす（物理エンジンの同期は、ずれや揺れの原因になりやすいため）。

**見送り：Unity と Photon Fusion 2**
- C#で書ける。ブロックやスティールの当たり判定に、ラグを補正する機能（Lag Compensation）が公式に用意されている。ただし、使えるのはServer ModeかHost Modeのときだけ。

**どちらを選んでも守ること**
- **ネットコードは後から付け足さない。** P1の段階からサーバー権威で書き、ローカルではホスト兼プレイヤー（listen server）で動かす。
- ブロックとスティールは、ラグを補正したうえでサーバーが判定する。
- 目標：144fps。ティックレートは60Hzから始める。

## 6. 3on3と5on5を両立させる方法

```
hero.skill.wall.width   : 3on3 ×0.8 / 5on5 ×1.0
hero.skill.*.cooldown   : 3on3 ×0.9 / 5on5 ×1.0
hero.ult.charge_rate    : 3on3 ×1.2 / 5on5 ×1.0
guard.max               : 3on3 ×1.0 / 5on5 ×1.1
```

## 7. 競合と差別化

- 一人称バスケはSteamに前例がある。**HoopsFPS**（最大3vs3のオンライン対戦）と **First Person Hooper**（1人用のシュートゲーム）だ。
- どちらも純粋なバスケで、**ロール・スキル・ウルト・連携の仕組みは持っていない**。ここが本作の差別化ポイントになる。
- ヒーロー制のスポーツゲームは、人が集まらないと続かない（Omega Strikersは発売から約8ヶ月でコンテンツ開発を終えた）。そのため、**ボットとの対戦で面白いことを先に証明する**。
