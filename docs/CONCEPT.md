# Basket Team-play TaG — ゲーム構想 v0.1

> ロール制チームアクション × バスケットボール。スマホ向け3D。
> キャラ・名前・ビジュアルはすべてオリジナル（既存タイトルの流用はしない）。

---

## 0. 三本柱（判断に迷ったらここに戻る）

| # | 柱 | 一言で |
|---|---|---|
| 1 | **協力が一番気持ちいい** | ソロで決める1点より、連携で決める1点のほうが得をする |
| 2 | **最後まで逆転の可能性がある** | 負けている側にも、腕前とチームワークで掴める逆転のチャンスが必ずある。ただし「施し」はしない |
| 3 | **スマホで快適** | 片手ずつの親指操作で完結し、エイムの精密さより判断とタイミングで勝負がつく |

## 1. 試合モード

3on3と5on5の両方を用意する。ヒーローは共通で、モードごとに数値の係数を変えて調整する（§6）。

| 項目 | 3on3「ストリート」 | 5on5「アリーナ」 |
|---|---|---|
| コート | ハーフコート・ゴール1つ | フルコート・ゴール2つ |
| ロール構成 | ウォール1 / スコアラー1 / プレイメーカー1 | ウォール1 / スコアラー2 / プレイメーカー2 |
| 得点 | インサイド1・アウトサイド2・ディープ3 | インサイド2・アウトサイド3・ディープ4 |
| 勝利条件 | 21点先取、または7分経過時点のリード | 前後半4分ずつ（計8分）の合計点 |
| ショットクロック | 12秒 | 20秒 |
| 想定試合時間 | 5〜7分 | 9〜11分 |
| 攻守交代 | ディフェンス側がボールを取ったら、アーク外へ出してから攻撃開始 | 通常どおりの攻守切り替え |

- 3on3の数値はFIBA 3x3の公式ルール（10分・21点・12秒）を元に、スマホ向けに短くした。
- ディープラインは3Pラインのさらに外に引く。遠くて決まりにくいぶん、決まれば1本で点差が大きく動く。

## 2. キルの扱い：キルはなくし、ダウンと仲間による即復帰にする

基本はA案（キルなし）。そのうえで「数的不利が生まれる緊張感」だけをもらい、**協力の見せ場**に変える。

- 各キャラは **ガードゲージ** を持つ。体の接触や相手スキルで削られる
- ゲージが0になると **ダウン（2.5秒）**。ボールを持っていればルーズボールになる
- 味方が触れると **即座に起き上がる**。起こした側と起こされた側の両方が1.5秒加速する
- 退場もリスポーン待ちもないので、ボールから離れた殴り合いにならない
- それでも「誰が起こしに行くか」という判断で一瞬の4on5が生まれ、チームの判断力が試される

→ キルありより協力の要素が濃く、テンポも崩れない。キルありに切り替える必要はないと判断した。

## 3. ロールとヒーロー（初期6体）

### ロールの役割
- **ウォール**：スクリーン、ゴール下の制圧、リバウンド。ガードゲージが多い
- **スコアラー**：得点源。1on1とシュートの性能が高い
- **プレイメーカー**：パス、味方の強化、ダウンした味方の復帰支援

### ヒーロー案（名前は仮）

| 名前 | ロール | スキル1 | スキル2 | ウルト | 連携ポイント |
|---|---|---|---|---|---|
| **ガンテツ** | ウォール | 前方に壁を4秒出す（パスとシュートを遮断） | ショルダーチャージで当てた相手のガードを大きく削る | 「鉄壁圏」：ゴール下の円の中で味方のブロック判定が拡大 | 壁の横を通った味方が加速する（スクリーン強化） |
| **ミナモ** | ウォール | 相手1人を数秒だけ引き寄せる | 自分の周りに減速フィールドを張る | 「渦」：エリア内の相手を中心へ集める | 引き寄せでマークを外し、フリーの味方を作る |
| **レイ** | スコアラー | 短距離ブリンクでドライブ | フェイダウェイで次のシュートをブロックされにくくする | 「ゾーン」：5秒間、シュートの成功判定が広がる | パスを受けた直後はブリンクのクールダウンが短くなる |
| **ハヤテ** | スコアラー | 次のシュートの射程を延ばす（ディープ向け） | バックステップで相手と距離を取る | 「ロックオン」：ブロックされないシュート。ただし溜めが長く、ダウンさせられると中断する | アシストを受けたディープシュートの成功判定が広がる |
| **ツムギ** | プレイメーカー | 壁を貫通する糸パス | 味方と糸でつながり、2人とも加速 | 「縫い寄せ」：味方1人を自分の隣にワープさせる | 糸でつながった味方がシュートするとチェインが+1 |
| **ヒビキ** | プレイメーカー | 音波で範囲内の相手のガードを削る | ダウンした味方を遠距離から起こす | 「共鳴」：範囲内の味方のスキルのクールダウンを即リセット | ウルト後にスキルをつなげるとシンクロ技が出やすい |

### 連携システム（コンセプトの核）
1. **チェイン**：パスを2秒以内につなぐたびに+1（最大3）。チェインが乗った状態のシュートは成功判定が広がり、ウルトもたくさん溜まる
2. **アシスト優遇**：ウルトの溜まり方は「アシスト1.5 ＞ 得点1.0」。点を取るよりつなぐほうが得をする
3. **シンクロ技**：味方2人が2秒以内に特定のスキルを重ねると、組み合わせごとの合体効果が出る（例：ツムギのワープ → レイのブリンク ＝ 遠距離からのアリウープ）
4. **ワンタッチ指示（ピン）**：「パスくれ」「スクリーン行く」「ウルトあり」「起こして」の4種。スマホではボイスチャットが前提にできないため必須

## 4. 逆転の仕組み（「最後までチャンスがある」の設計）

### 原則
- 逆転は **チャンスと腕前** で起きるようにし、負けている側への一方的なボーナスや、勝っている側へのペナルティにはしない
- 逆転しやすさを強くしすぎると序盤のリードが無意味になり、弱すぎると逆転が起きない。このバランスを数値で管理する
- 参考：Riotはカムバック要素について「上手くプレイしたチームが報われ、下手なプレイは罰せられるべきだ」と述べ、どちらかに振れすぎた場合の失敗も挙げている。Pokémon UNITEは終盤2分の得点を2倍にして逆転の余地を残している

### 仕組み
| 仕組み | 内容 | 狙い |
|---|---|---|
| **クラッチタイム** | 残り1分（3on3）／後半残り1分（5on5）になると、ディープラインが少し前に出る | ハイリスク・ハイリターンの選択肢を、負けている側が取りやすくする |
| **ゴールデンボール** | クラッチタイムの開始時、コート中央に中立のボールが出る。奪って決めると＋3点（3on3）／＋5点（5on5） | 両チームが奪い合う目標。勝っている側も取れるので施しにはならない |
| **ストップの報酬** | ブロックとスティールで溜まるウルト量を多めにする | 守備でも流れを変えられるようにする |
| **スコアは常に表示** | 点差は隠さない | 「あと何本でひっくり返せるか」が見えることで、粘る理由になる |

### ガードレール（初期の目標値。実際に遊んで調整する）
- クラッチタイムでの最大の点差の動きは、3on3で約8点、5on5で約12点とする。それより開いていれば、勝っている側がほぼ逃げ切れる
- 指標：「クラッチタイム開始時点で負けていた側の勝率」が **20〜30%** に収まるように調整する（0%に近ければ逆転が起きず、50%に近ければ序盤が無意味）

## 5. スマホでの3Dの作り方

### カメラ
- **斜め上からの中継風カメラ**（横持ち）。フルコートが画面の横幅に収まり、パスの先が見える
- 3on3はズームを寄せ、5on5は少し引く
- 一人称や背後視点は採用しない。スマホでは視野と精密なエイムが足りないため

### 操作（横持ち・両手の親指）
| 場所 | ボールを持っているとき | 守っているとき |
|---|---|---|
| 左 | 移動スティック | 移動スティック |
| 右・大ボタン | **シュート**：押して溜め、離すタイミングで判定 | **ジャンプ／ブロック** |
| 右・中ボタン | **パス**：タップで移動方向にいる味方へ、ドラッグで相手を選択 | **スティール** |
| 右・小ボタン×2 | スキル1・2（タップで自動ターゲット、ドラッグでエイム） | 同じ |
| 右上 | ウルト | ウルト |

- スキルは、ボタンを押したままドラッグするとその場で照準用のスティックが出る方式（Wild Riftと同じ）
- シュートは自動でゴールを狙う。成否は **位置・相手との距離・離すタイミング・チェイン** で決まり、指先のエイムの精密さは問わない

### 技術スタック（案）
- **Unity + URP**（第1候補）。モバイル向けの最適化手順が公式ドキュメントにまとまっているため。対抗馬はGodot 4のMobileレンダラー
- 最適化の初期方針（Unity公式URPドキュメントより）
  - SRP Batcherを有効にし、対応したシェーダーだけを使う
  - カメラは1台にし、不要なDepth/Opaque TextureとHDRは切る
  - 低スペック端末ではレンダースケールを下げる
  - 静的なものにはBaked Lit、動くものにはSimple Litを使う
- 見た目：ローポリのトゥーン調にする。描画が軽く、小さな画面でも見分けやすい
- 目標：中位のAndroid端末で60fps、低位の端末で30fps

## 6. 3on3と5on5を両立させる方法

ヒーローのデータに **モードごとの係数** を持たせ、1つのキットのまま両モードで成り立つようにする。

```
hero.skill.wall.width   : 3on3 ×0.8 / 5on5 ×1.0   # ハーフコートでは壁を小さく
hero.skill.*.cooldown   : 3on3 ×0.9 / 5on5 ×1.0   # 少人数のほうが試合のテンポが速い
hero.ult.charge_rate    : 3on3 ×1.2 / 5on5 ×1.0   # 試合が短いぶんウルトを早く溜める
guard.max               : 3on3 ×1.0 / 5on5 ×1.1
```

## 7. 開発ロードマップ

| フェーズ | 中身 | 完了条件 |
|---|---|---|
| P0 | 紙とホワイトボードでのルール検証 | 1試合が成り立つ |
| P1 | 1on1：移動・ドリブル・シュート・ブロックをスマホの実機で触れる状態にする | 操作が気持ちいい |
| P2 | 3on3 vs bot：ロール3体・チェイン・ダウンと復帰を入れる | 連携で点を取るほうが楽しい |
| P3 | 逆転の仕組みと6体のヒーローを入れる | 逆転率の指標が取れる |
| P4 | オンライン対戦、5on5 | 2台の端末で対戦できる |

**ボットとの対戦で面白くなければオンラインには進まない。**（Omega Strikersは人を集められず、発売から約8ヶ月でコンテンツ開発を終えた）
